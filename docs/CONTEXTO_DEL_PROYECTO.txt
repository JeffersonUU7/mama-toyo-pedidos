-----------------------------------------------------------------------
DE QUE TRATA
-----------------------------------------------------------------------
Sistema web de pedidos para llevar y menu del dia para el Comedor
Mama Toyo (San Miguel, El Salvador). El local es pequeno y en el
almuerzo se forman filas. El sitio permite ver el menu, pedir con
anticipacion y le da a la cocina una lista de pedidos pendientes.

El menu y los precios son los del Comedor Mama Toyo (ver docs/MENU.md).
Cada plato tiene un precio minimo y uno maximo.
El proyecto corre en local con Docker; no se publica en internet.

Objetivo tecnico: integrar las tres unidades del curso en un solo sistema:
  - Unidades 1 y 2: contenedor web Express/TypeScript + servidor web
    (Apache o IIS) con HTTPS (certificado autofirmado en local).
  - Unidad 3: cluster activo-activo de al menos 2 nodos en Docker
    Compose, con health check y balanceador Nginx (con HTTPS).


-----------------------------------------------------------------------
ARQUITECTURA
-----------------------------------------------------------------------
  Cliente --HTTPS--> Nginx (balanceador) --> Nodo 1 (Express) /health
                                         \-> Nodo 2 (Express) /health


-----------------------------------------------------------------------
RUTAS DE LA APLICACION (src/app.ts)
-----------------------------------------------------------------------
  GET  /api/health            200 si el contenedor funciona
  GET  /api/menu              platos del dia con precio minimo y maximo
  POST /api/pedidos           crea un pedido {cliente, items:[{platoId,cantidad}]}
  GET  /api/pedidos/:numero   consulta un pedido
  GET  /api/cocina            pedidos pendientes en orden de llegada

Las mismas rutas existen sin el prefijo /api (por ejemplo /health): las
usan Nginx, el health check de Docker y las pruebas de carga.
Cada respuesta incluye el campo "node" (que nodo la atendio).

COMO CORRERLO
-----------------------------------------------------------------------
  Sin Docker:    npm install   y luego   npm run dev   (puerto 3000)
  Fase 2:        bash certs/generar-certificado.sh   y luego
                 docker compose -f apache/docker-compose.apache.yml up --build
                 (entrar por https://localhost:8443)
  Con cluster:   docker compose up --build   (entrar por el puerto 8080)
  Simular falla: docker compose stop app1

Tecnologias: Node.js 20, Express, TypeScript (strict), Docker y Docker
Compose, Nginx, Git y GitHub.

-----------------------------------------------------------------------
DECISIONES TOMADAS (detalle en docs/DECISIONES.md)
-----------------------------------------------------------------------
  1. Pedidos: se guardan en PostgreSQL (servicio en Docker Compose), para
     que los dos nodos vean los mismos pedidos. Sin DATABASE_URL la app
     usa memoria, para poder correr npm run dev sin Docker.
  2. Entrada: Nginx es el punto de entrada unico (HTTPS) y balancea hacia
     dos nodos; cada nodo tiene su Apache y su Express. Se construye por
     etapas. Plan B: Apache delante de Nginx.
  3. Health check: Nginx pasivo + HEALTHCHECK de Docker en /health.
  4. Precios: se mantienen como rangos (minimo y maximo), igual que en
     docs/MENU.md.
  5. Marcar un pedido como listo: PATCH /api/pedidos/:numero (despues de la
     persistencia).
